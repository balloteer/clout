# First-pass integration and security review

This review covers the local implementation and focused automated tests. It is not an independent production audit, a complete funded user-flow rehearsal, a physical Android device certification or approval for mainnet. Devnet provisioning and the sample-market registry are tracked separately in their public artifacts.

## Findings addressed

- Wallet identity: sign-in verifies the exact server-issued UTF-8 message with Ed25519, a five-minute single-use nonce and the pinned origin. Session tokens are hashed server-side. Mobile Wallet Adapter's signed payload includes the signature suffix; the client separates that suffix and verifies the message bytes before submitting authentication.
- Payment interruption: user transactions persist their signature before broadcast. Confirmation and new submission share a per-wallet lock; a reproduced cross-screen race is covered by a regression test so a late confirmation cannot delete a newer pending transaction. The API stores the exact unsigned intent, refuses another wallet's confirmation, and reconciles the executed message and actual token debit/credit. Trade retries reuse the same intent. Launch retries preserve the prepared name/ticker; changed metadata is rejected. Tip retries bind recipient, amount and request ID.
- Reward interruption: treasury transactions persist signed bytes and signature before broadcasting. Lease compare-and-swap protects concurrent workers. Unknown outcomes retry the same bytes; only finalized onchain failure permits a bounded replacement. Missing history after expiry requires operator review and can never trigger another payout. Campaign changes are blocked while prior claims remain unresolved. Unique wallet, SGT and signature constraints prevent duplicate campaign payment. The API exposes no signed payout bytes.
- Social identity changes: sample preferences remain device-local; real likes and follows hydrate from the current wallet's server state, while saved live posts use wallet-scoped storage. Epoch checks ignore responses from a previous wallet. Concurrent like/follow operations for the same target are blocked, and server like counts avoid double addition.
- Devnet identity boundary: the running alpha constructs no mainnet RPC client. SGT verification and `.skr` resolution are unavailable rather than reporting false ineligibility. Retained future verifier modules are covered by isolated tests, but the server does not wire them into authentication, rewards or profiles.
- Media: Cloudflare callback HMAC binds the raw request bytes and timestamp. Unsigned callbacks cannot publish posts, and replay cannot regress ready media. Own processing/failed posts cannot launch markets.
- Market boundary: the SDK remains in the market package, uses explicit devnet Test SKR, integer amounts, bounded slippage, expiring quotes, fixed creator fee policy and simulated allowlisted transactions. Genesis checks use the full RPC hash. Confirmed purchases become early-backer receipts only after finalization.
- Chart provenance: post activity contains real executions reconciled through Clout intents, with decimals and finality. Empty history remains empty; it does not imply protocol-wide indexing.
- Owned X accounts: a review reproduced the forwarded-start-URL ownership risk in the initial callback design. The corrected flow creates only an encrypted pending grant at the browser callback. The callback-only completion secret, locally retained app verifier, initiating state and exact authenticated wallet/session must all match before a link is committed. Postgres commits the account and a short idempotent receipt atomically. Completion secrets have no polling endpoint. Native return uses `attempt`, since React Navigation reserves `state` as a query parameter.
- Import boundaries: three combined accounts are enforced under a database wallet lock and trigger; account actions are owner-only. Unique source IDs prevent duplicate posts. Imports request no X write permission, accept only owned new public single-video posts and exact provider media URLs, and never launch markets. An uncertain Cloudflare copy cannot trigger a second copy; signed callbacks and authenticated polling can recover a known processing upload.
- Mock mint recovery: bounded faucet reservations reuse durable payout leases and commit exact signed bytes before send. Only finalized transactions appear minted. A restart after an onchain mint but before DB confirmation now verifies network/authority without demanding the same supply allocation twice, then reconciles the existing signature. Missing history still requires review and cannot authorize replacement.
- Licensed samples: the API serves only the 50 catalogued video/poster filenames with bounded single-range seeking in both modes. Registry markets point to finalized devnet transactions. Registered sample creator wallets have explicit operator profiles, so profile navigation and Follow no longer fail after adding market references.

## October 13 daily faucet and Seeker routing review

The daily faucet uses exactly 1,000 mock SKR per wallet per UTC day. Its SQL reservation reads the database clock after taking the campaign lock, enforces wallet/day uniqueness and increments a permanent supply budget in the same transaction. Midnight does not clear that budget. Unresolved earlier claims, including ambiguous expiry, block replacement; recovery scans every pending page and broadcasts only persisted signed bytes. The authority must remain dedicated to this ledger because standard SPL minting does not enforce an application supply ceiling.

Native routing checks production Seed Vault Wallet packages and published signing certificates before launching an explicit Android component. The browser retains the official Seeker endpoint. Both request devnet, check account continuity, and invalidate older sessions. Endpoint routing is not device attestation: the API authenticates a wallet key, and the quota is per wallet, not per physical phone. Mainnet SGT verification remains disabled.

The focused parallel review found no new critical issue in those paths. The complete suite passes 174 tests, including actual SQL migration/permission checks, UTC rollover, concurrent requests, restart recovery, endpoint rejection and replay prevention. Workspace lint, the web production build and Android bundle export pass. The owner confirmed physical Seeker login and a 1,000 SKR claim; physical trading and public API deployment remain release gates; the browser relay requires the developer to accept its terms.

## Native wallet compatibility repair

The old native transport incorrectly required an exact returned `wallet_uri_base`, although the MWA specification makes it optional. The owner reproduced the corresponding rejection message. The native adapter now verifies the installed production package/certificate independently of response metadata, requires its native routing module before opening a session, and fetches/signs the challenge within one association. A rejected cached authorization gets one fresh attempt, with stale in-memory and stored authorization discarded if that attempt is interrupted. API availability is checked before wallet launch. User cancellation stays distinct from unavailable servers and real wallet failures. Positive physical login/faucet confirmation came from the owner; emulator checks separately reject Fakewallet and explain missing USB API forwarding.
