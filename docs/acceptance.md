# Implementation and release acceptance

Clout uses the supplied branding and **Seek the best content, win SKR**. The current alpha is mobile-focused and runs entirely on Solana devnet, including server identity behavior. Market quotes, sales, creator fees and the faucet use the same six-decimal mock SKR mint. No other payment token substitutes for SKR.

The preview feed now has 62 active posts: the 50 bundled sample clips plus [12 reviewed portrait Solana, SKR and AI videos](curated-content.md) streamed from X. All active videos have finalized devnet markets. The 18 older curated posts remain addressable through saved collections and held positions, preserving all 68 original registrations within the 80-market registry. Curated source attribution is separate from the Clout demo-market operator. Browser wheel, trackpad and touch inputs snap to a complete post.

Local verification through October 14, 2026 covers the API, mobile client, market adapter and setup helpers. The automated suite has 243 tests (119 API, 53 mobile, 4 native-plugin, 41 markets and 26 setup checks). Typechecking, linting, formatting and the web production build pass; the updated portable Android build is tracked in [android.md](android.md).

The isolated devnet payer was funded by the owner. Mock SKR, separate sample/rehearsal pool configurations and all 80 catalog markets are provisioned. The shared registry contains public finalized launch signatures and addresses; private keys and transaction journals remain in ignored `.tooling/devnet/`. Live rehearsal reports are `artifacts/devnet-trade-rehearsal.json` and `artifacts/devnet-graduation-rehearsal.json`. These prove SDK/on-chain execution using task wallets; they do not prove an end-user APK-to-hosted-API flow.

Only public catalog metadata was deployed to [clout-devnet-catalog.vercel.app](https://clout-devnet-catalog.vercel.app). The app/API have not been deployed there. The current USB preview embeds the loopback API and requires the Mac API plus USB forwarding for connected services. A portable connected build now requires an explicit matching public HTTPS API and wallet identity origin. No mainnet transactions or app-store submissions occurred. Mock SKR and post position tokens have no monetary value. Optional Genesis NFTs, auctions, crates, direct messages and a secondary NFT marketplace remain outside this release.

## Mobile review evidence

The parallel reviews corrected variable-aspect video, undersized touch targets, a guest wallet-connect action that could not be pressed, lost feed position after tab navigation, text overflow, hidden caption fields and controls that crowded the smallest phone layout. The October 13 browser revision fixes the clipped Create publish action, pins Discover search/categories, and moves investment to an eye button above Like in a fixed action rail. See [mobile-layout.md](mobile-layout.md) for reference research and viewport checks. The feed scrolls vertically with native paging. Adjacent items show posters while only the active item owns a player. Opening a modal pauses playback and closing it resumes playback.

The frame uses Seeker's published 1200:2670 (40:89) panel ratio from [Solana Mobile](https://solanamobile.com/seeker). Phone header/navigation controls overlay the video using safe-area offsets. Desktop and differently proportioned screens fit the same frame without stretching. A 400×890 browser viewport and Android 1200×2670 at 480 dpi are proportional test profiles, not claims about the handset's default Android density. A second emulator profile uses 460 dpi, and enlarged text is checked up to 150%.

`node scripts/verify-web.mjs` covers video geometry, vertical paging, controls, playback, modal behavior, recovery and navigation. `node scripts/review-buttons.mjs` exercises 19 mobile flows, including the menu, faucet, linked-account wallet gate, sharing and the file picker. Native screenshots and accessibility trees live under ignored `artifacts/native-review`. See [devnet-alpha.md](devnet-alpha.md) for the remaining service setup.

## Daily faucet verification

On October 13, the actual HTTP/auth/faucet services and production repository SQL ran against a file-backed PGlite database using an isolated task wallet. The recipient received exactly 1,000 mock SKR in [this finalized devnet transaction](https://explorer.solana.com/tx/4fT3rQ5t17YkcuAzygcokp6345dVbKFqP6TbgaQE2KcNjXEY8txVF84gt4FuzNHQuHkBrUiMaF7tWP23PRVHrA82?cluster=devnet). Concurrent requests returned one claim. Closing and reopening the database and retrying returned the same claim/signature without increasing the balance. This verifies the backend payout; it does not substitute for hosted Supabase or Seeker hardware testing.

`node scripts/verify-devnet-faucet.mjs` is read-only by default. `--self-test` checks the SQL adapter without RPC; `--execute` explicitly runs the isolated devnet rehearsal and preserves its recipient/database/journal for retries. It refuses minting again on another UTC day. Private files remain ignored under `.tooling/devnet/faucet-rehearsal/`.

The four faucet UI states—available, claimed, pending and needs review—passed at 400×890 with the main action visible without scrolling. `scripts/review-daily-faucet-ui.mjs` uses explicit UI fixtures and no chain writes.

The owner confirmed successful login and a 1,000 mock SKR mint on the physical Seeker after installing version 0.1.2 (3).
